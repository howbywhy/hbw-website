## Fixed in this pass

**The page could lose its scroll.** The gallery, About and the poster tool
each saved `body.style.overflow`, set it to hidden, and put the saved value
back. Correct for one holder, wrong for two: About saved "hidden" because the
gallery was already holding, and on the way out the gallery cleared the lock
and About put it back after. Leaving a project through About left the front
page unable to scroll. Now one counted lock in `scroll-lock.ts` — captured by
the first holder, restored when the last lets go. Guarded by `qa/checks/scrollback.mjs`,
which walks six routes and fails only when the scroll is held with nothing
left to hold it.

**One flick of the wheel moved About on by two blocks.** The pause that stops
a trackpad's tail opening a second block lived in the wheel listener's own
scope, and the listener was rebuilt whenever the reading moved — so opening a
block threw away the pause meant to protect it. The first part went straight
through the second to the third. The pause lives outside the effect now.

**The positioning line vanished.** At full bleed the gallery's own row carries
the studio line and the bar stands its copy down, to dodge a Chrome paint bug.
Open About over a full-bleed frame and that row is behind the sheet, so nothing
was carrying the words. The bar takes the line back whenever a sheet is over
the gallery, on a fade rather than a switch.

**7.5MB of film on every page.** The strip fetched its films for "the first
project", but Work only ever runs the *first film of the project being read* —
so three of four were fetched and never played. And "the first screen" meant
"every cell of the first project", which held while the first project was a
long one; the newest is an eight-frame launch, so eight of eighty-eight visible
cells loaded eagerly and eighty arrived late.

**A check that cried wolf.** The console check counted an aborted media range
request as a missing file, calling four working films missing on every page. It
now distinguishes an abort from a failure, and still fails on a film that
genuinely cannot load — proved by breaking one.

**A check that had been red so long it checked nothing.** `validate-studio-docs`
asserted CLOSED had 22 movements while it had 18, so it threw on the first
project and the other five were never validated. It counts from the copy now.

**Dead code.** `IdentityNav.tsx` (321 lines), `poster/recognise.ts`,
`poster/smooth.ts` — nothing imported them. A duplicate `"Digital Design"` in
the adapter's discipline list is gone.

## Suggested improvements, worst first

**1. `reference/` is 686MB and 9,926 files, committed.** The pack is 772MB, so
the archive is nine tenths of the repository. Every clone and every Vercel
build pulls it. Move it to its own archive repo, or strip it from history with
`git filter-repo`. This is the single biggest thing in the codebase and it
does not ship.

**2. ~3,760 lines exist only for the CMS preview.** `HbwShell`, `WorkScroll`,
`WorkDetail`, `IndexDetail`, `WorkspacePanel`, `ProjectsNavPreview` and the
`index-marks.ts` logotypes are reachable only through `/preview/[slug]`. The
public site is the `site/` tree. Either point `/preview` at the live `Work`
components and retire the old shell, or keep it and say so in its header — at
the moment it reads as the main codebase and is not.

**3. Adding a project touches five files.** `catalog.ts`, `cms-source.ts`,
`experiences.ts`, a content module and a seed script, plus a logotype if the
index is kept. `generateStaticParams` reads the shipped catalogue, so a
CMS-only project gets no page at all. This is what `studio/project-registry`
was for; it is worth finishing — roughly half a day.

**4. The six CMS verifiers are near-identical copies**, 1,090 lines between
them. One parameterised verifier driven by the registry would cut that to
about 200 and mean a seventh project is verified by existing.

**5. Made by Madelen has no logotype.** The index falls through to nothing for
it. Needs the real vector — I did not want to draw a client's mark. It is
recorded by name in `WITHOUT_A_MARK` in `load-index.test.ts`; take it off that
list when the SVG lands.

**6. CLOSED's published preview image has drifted** from the shipped record:
Sanity carries `HBWxCLOSED-Portfolio-01.jpg` at 1920×1080, the catalogue
expects `...Portfolio25.jpg` at 1080×1350. Harmless today because the card is
drawn from the sequence, but the verifier reports it on every run, and a
reported-but-ignored gap is how the 22-vs-18 one survived.

**7. There is no `npm run lint`** and no ESLint config. Typecheck and tests
carry the whole load.

**8. Only 2 of 52 films have a webm.** The rest are mp4 only. WebM would cut
Chrome and Firefox bytes meaningfully now that the heaviest films are a
launch made of motion.

**9. `hbw-index.css` is 13,390 lines in one file.** It reads well and is
heavily commented, but finding the rule that owns a behaviour means grep.
Splitting by room — bar, gallery, sheet, catalogue, writing — would not change
a pixel.

**10. Rules keyed to "the first project" keep breaking.** Two of this pass's
bugs were that shape. Worth a look wherever else identity stands in for
position.
